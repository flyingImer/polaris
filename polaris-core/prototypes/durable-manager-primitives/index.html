同一份 Manager，怎么安全地提交？

要验证的问题：Manager 只表达业务读取和最终修改，换一种 Primitives 并发保护机制后，这套流程还能正确处理冲突、部分失败和 Unknown 吗？先点「读取并准备」，观察候选修改与已发布数据的区别。

这是内存中的可操作模型。没有连接数据库，没有运行 Polaris Java，也不代表 FDB、Spanner 或 JDBC 已通过验证。刷新页面会清空状态。

两个模型都保留一致的读取快照，并模拟一次原子提交。整个 scope 的 version 更保守，无关修改也可能让它冲突。切换选项会重置场景。
